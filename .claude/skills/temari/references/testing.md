## Testing

- **1:1 class↔test.** Every concrete class has a `{Name}Test.php`, or is exempt in [tests/Unit/Architecture/EveryClassHasATestTest.php](../../../../tests/Unit/Architecture/EveryClassHasATestTest.php). Frontend: co-located `{name}.test.tsx`, guarded by [resources/js/test/structure.test.ts](../../../../resources/js/test/structure.test.ts). `database/seeders/Demo` is outside the guard (it scans `app/`) and is covered end to end by `DemoSeedCommandTest`. A design-catalogue `*.examples.tsx` needs no test of its own: [catalogue-examples.test.tsx](../../../../resources/js/test/catalogue-examples.test.tsx) renders every one.
- **Unit tests avoid the DB** unless the class needs persisted state; mock collaborators instead.
- **No mutation testing** (Infection or `pest --mutate`).
- **Aggregate suites** cover whole families: narrators → `NarratorsCoverageTest`, agent tools → `AgentToolsCoverageTest`, AI jobs → `JobsCoverageTest`. A new narrator, job or agent tool needs a real marker in its suite (or its own `{Name}Test.php`): a `->with()`/`dataset()` entry keyed by `Foo::class`, or `->covers(Foo::class)` on a test about that class alone. A mention in a comment, a test name or a plain `new Foo` doesn't count, and `EveryClassHasATestTest` fails on a class in those namespaces with neither. Prefer the dataset key, since `covers()` narrows that test's coverage to the named class. A new tool's key goes in the tool-shape test and a new analyze job's in the narration-queue test, which each run every member; a narrator is keyed in the prompt-rule datasets that apply to it.
- Structure tests live in the `structure` group and run **before** coverage in CI (fast fail). Gate: 95% line+function coverage, plus a 93% branch floor on the frontend.
- **DB isolation is per-file opt-in**, not global. A DB-touching test adds `uses(RefreshDatabase::class)`; the architecture/enum/geo/calculator tests stay DB-free on purpose, and the CI `structure` gate runs with **no DB** — so a suite-wide `uses(...)->in('Feature','Unit')` breaks them (they'd connect to an unreachable host and the gate fails). `RefreshDatabase` transacts both the default `mysql` and the second `analytics` connection (`$connectionsToTransact` in [tests/TestCase.php](../../../../tests/TestCase.php), which rebinds `analytics` to the test DB in `setUpTraits`). Do **not** switch to `LazilyRefreshDatabase`: its deferred, manager-level trigger doesn't wrap the purged-and-rebound `analytics` connection, so `ai_token_usages` writes leak across tests.
- **Test speed lives in fixtures, not the trait.** The suite is parallel and DB-bound; the long pole is heavy-seed tests, not transaction overhead. The clearest case was `DemoSeedCommandTest` re-running the full ~81-run demo seed once per assertion-test (~52% of serial runtime) — consolidated to seed once and assert many (the idempotency test keeps its own two seeds), cutting `--processes=4` wall-clock ~27%. Mocking a class's injected siblings does **not** cut time: services/jobs own their DB access (`Model::query()` in their own bodies; jobs resolve their model in `handle()`), and controllers can't shed the DB because [HandleInertiaRequests](../../../../app/Http/Middleware/HandleInertiaRequests.php) queries the auth user's shared props on every page load. Frontend `fetch` defaults to a safe 404 stub in [resources/js/test/setup.ts](../../../../resources/js/test/setup.ts); override per-test only when asserting specific calls.
- **PHPStan covers `tests/` at level 9** (the directories listed under `paths` in [phpstan.neon](../../../../phpstan.neon)). Pest closures are typed by the extensions in [tests/PHPStan](../../../../tests/PHPStan): `$this` inside `test()`/`it()`/`beforeEach()`/`afterEach()` and `pest()->beforeEach()` is `Tests\TestCase`, `test()` with no arguments is the `TestCase`, and `$this->artisan()` is a `PendingCommand`, so `->assertSuccessful()`/`->expectsOutput*()` need no per-call narrowing. A Mockery mock that a test sets properties on or returns as its class is built by a typed helper in [tests/Pest.php](../../../../tests/Pest.php) (`socialiteUserMock()`), or carries a `@var Foo&MockInterface` tag where it is created. A nullable value that is *used* (a method call whose effect is asserted later, or a value passed on) is asserted non-null first with `expect($x)->not->toBeNull()` (it still fails with assertions off), narrowed with `assert($x !== null)`, then called with `->`; never `$x?->call()`, which skips the call and lets the test pass with nothing run. `?->` is for a final read that is itself compared with `toBe(...)`/`toEqual(...)`/`toBeTrue()`/`toBeFalse()` against a non-null value, where null already fails; where the assertion could pass on null (`toBeNull()`, `not->toBe()`), use `refresh()` or the non-null assertion above. Never add `@property` tags to `TestCase` for per-file state.
  Per-file fixtures are typed functions, not `$this->x` set in `beforeEach()`; keep `beforeEach()` for setup that has no value to hand on:

  ```php
  // before: beforeEach(fn () => $this->brokenAt = Carbon::parse('2026-10-14 06:15:00'));  … $this->brokenAt
  function brokenAt(): Carbon
  {
      return Carbon::parse('2026-10-14 06:15:00');
  }
  // after: … new IntervalsIcuDisconnectedNotification(brokenAt())
  ```

  A value that is built per test (a spy, a fake) stays a typed local: `$log = Log::spy()` then `$log->shouldHaveReceived(...)`, `$queue = Queue::fake()` then `$queue->pushed(...)`. A `$user->fresh()` passed as a `User` becomes `$user->refresh()`.

  Pest types `toThrow()`'s closure as `Closure(Throwable): mixed`, so `toThrow(fn (FooException $e) => …)` fails level 9 and `Throwable $e` is read as a message. Catch the exception in a small typed helper and assert on what it returns, as `retryAfterOfTransientFailure()` does in `IdempotentWebPushChannelTest`.
