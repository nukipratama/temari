# Move the toolchain to Node 26

**Status:** Accepted (owner call, 2026-10-07, in #1982; built in #1945 and #1944)

## Context

[[2026-09-30-audit-considered-and-rejected]] held the runtime on Node 24 and left the move to Node 26 until the toolchain listed it as supported and it had settled into LTS. Node is used only in the asset-build stage and the dev image, so the runtime image has none.

## Decision

We decided to upgrade to Node 26 with `@types/node` 26 inside the audit epic, moving the pieces that name the major together:

- `engines` in [package.json](../../package.json) is `>=26 <27`, and `@types/node` is `^26`.
- [.nvmrc](../../.nvmrc) pins the same 26.x build that CI reads.
- The [Dockerfile](../../Dockerfile) `node-src` stage uses the matching `node:26.x-alpine` tag and its digest, so dev, CI and the assets build run one Node.
- The Dependabot `node` and `@types/node` major ignores in [dependabot.yml](../../.github/dependabot.yml) stay, so 27 is not proposed.

## Open step

The pinned build is the newest 26.x image Docker Hub publishes, not an LTS-tagged one. After 2026-10-28, re-pin `.nvmrc`, the Dockerfile tag and digest to the first LTS-tagged 26 build, before the epic merges.

## Consequences

- The typecheck now accepts Node 26 APIs, which match what the build scripts and tests run on.
- A future move to Node 27 is a deliberate, owner-timed change across the same four places, not a bot proposal.
