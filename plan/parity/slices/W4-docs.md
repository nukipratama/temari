## Four dead tokens

`--color-phase-{base,build,peak,taper}` are declared at `app.css:267-270` and referenced by nothing
in `resources/js`, `app/` or `tests/`. `F2` promoted four `PHASE_COLOR` hexes to tokens; the
periodization display went on using `PHASE_COLORS` in `chartTokens.ts:118`, a different set with a
fifth `deload` key the tokens never had. `W2`'s sweep missed them.

**Ruled by the user: delete the declarations and the doc section**, rather than documenting them as
reserved. The two sets disagree, so leaving them is how the wrong one gets picked up later. The
deletion is pinned by adding `--color-phase-` to `DesignTokenDocsTest`'s `$forbidden` list, which is
that test's own anti-decay mechanism.

## The citation guard has a hole, and it is sized

`scripts/check-doc-citations.php` does check line drift, within a ±15 window — but only when the
link *text* names a symbol it can find. Two ways a citation escapes it:

1. **The link text is a filename.** `[app.tsx:19](resources/js/app.tsx#L19)` names no symbol, so
   `symbolCandidates()` returns nothing and the check returns early. **65 of the 359 `#L` citations
   across 13 docs are written this way**, `frontend-architecture.md` worst at 9 — and most of its
   nine have in fact drifted, which is why the audit found them and CI did not.
2. **The link text is PascalCase.** `symbolCandidates()` excludes PascalCase deliberately, on the
   reasoning that "a PascalCase one is usually the class itself, which sits near line 1 of its own
   file". True for `[Foo](Foo.php#L12)`; false for a *usage site* in another file. Measured: exactly
   **one** citation repo-wide falls in that hole — `[ErrorBoundary](resources/js/app.tsx#L27)`,
   which is genuinely wrong (real hits at L6/L77/L79).

**Ruled by the user: sweep all 65 and widen the guard.** The sweep converts each filename link text
to the symbol it points at, bringing them under the checker; the guard gains PascalCase when the
cited file is not the symbol's own file. Both are self-proving — every already-drifted citation
turns the guard red the moment it comes under coverage, and the widened rule starts by catching
`ErrorBoundary` rather than nothing.

## `T2`'s open question, closed

`T2` stepped the root font-size 20% at ≥1280px and left this open: nothing stops a new `text-[Npx]`
from silently opting out. Measured first — **there are zero `text-[Npx]` in `resources/js` today**,
so a guard starts green. The canvas `ctx.font` strings in `shareCard.ts` are legitimately px (a
fixed-size raster, not a scaled viewport) and a class-shaped regex does not reach them.

**Ruled by the user: guard both forms, and fix the one live instance.** `BrandMark.tsx:34` sets
`style={{ fontSize: 20 }}` on the wordmark, which holds at 20px while every sibling grows past
1280px. It becomes a token.

The new rules follow rule 3's precedent from `F2`: a rule change ships with a regression test in
`check-raw-palette.test.ts` proving it still rejects an off-scale value, so the rule cannot later go
quietly empty.

## Acceptance criteria

1. No claim in the table above survives, and each correction is verified against source rather than
   against the audit that found it.
2. A dark-default ADR exists, records decision 6 with its consequences (dawn-shift's retirement, the
   `-ink` inversion, both grounds scored by `DesignTokenContrastTest`, the pre-paint theme script),
   and is linked from `docs/decisions/index.md`.
3. Zero filename-as-link-text `#L` citations remain in `docs/`; the count is asserted, not eyeballed.
4. The widened guard **fails** on the `ErrorBoundary` citation before that citation is fixed, proven
   by running it, not assumed.
5. Both new `check:palette` rules reject a deliberately-introduced violation, proven the same way,
   and `shareCard.ts`'s canvas fonts do not trip them.
6. `--color-phase-*` is gone from `app.css` and from `design-tokens.md`, and re-introducing the name
   into any of the four design docs fails `DesignTokenDocsTest`.
7. `check-doc-citations.php`, `check:palette`, `check:chunks`, `check-see-references.php`, the full
   PHP suite and the frontend suite are green, each run directly.
