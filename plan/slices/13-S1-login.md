# S1 — Login

**Wave** 2b · **Slot** parallel worktree · **Blockers** `F4` · **Status** in-review

## Goal

Port `pages/Auth/Login.tsx` (479 L) onto `BareShell`. The tightest budget in the program: capped at
160 kB gz, framer-motion-free (R6). Restricted to Base-UI-free primitives (`button`, `card`, `badge`)
— `toggle`, `toggle-group` and `collapsible` are out of bounds here.

Carries the copywriter rubric's open question: the prototype's all-lowercase treatment was agreed
for Login specifically. Whether that stays Login-only or extends is ruled in `L0`; if unruled by the
time this slice starts, escalate rather than guessing.

Per the copywriter rubric ([verification/copywriter.md](../verification/copywriter.md), §3):

> The prototype renders essentially everything lowercase, including the wordmark and button labels.
> That treatment was agreed for the **login mockup specifically** and diverges from
> `voice-and-tone.md` on purpose. Whether it extends to the other ten screens is **undecided**. Any
> slice that applies all-lowercase beyond Login must say so in its slice doc and get an explicit
> ruling — it is not a silent styling choice.

This slice applies the lowercase treatment to Login only, per that ruling. No other screen is
touched.

## What actually landed

**A visual restyle, not a content rewrite.** All of the shipped page's real, props-driven content
survives: `KartuMini`'s live collectible-card render, the `dataUse` and `trainingDisclaimer`
server-sourced blocks, the `demoLoginEnabled` gate, the `ConnectPanel` Strava flow, and the full
`MATCHING`/`GETS` feature-list copy. What changed is layout (ported onto the prototype's structure)
and casing (lowercase-start, per the ruling above), not the underlying facts.

**Connect panel moved to a single overlapping card, dropping the old duplicate bottom CTA.** The
pre-port page rendered `ConnectPanel` twice: once inside a two-column desktop hero grid, once again
in a "Ready when you are" card near the footer. The prototype's own design has exactly one connect
card, placed directly under the hero with a small negative-margin overlap
(`-mt-10`/`-mt-14` responsive). Porting onto that design meant collapsing to the one card — no
functionality is lost (same Strava-connect anchor, same demo-login button, same fine print), only a
repeated affordance. This is a structural port call, distinct from the reconciliation ledger's
named content-preservation items below, which are all still present.

**`Collapsible` avoided by design, per R6.** The prototype's own "data & AI use" section is a
`Collapsible`. Base UI's collapsible pulls in a portal that blows the 160 kB budget on this route
(see `plan/README.md` R6), so `dataUse` and `trainingDisclaimer` are each rendered as their own
always-expanded `Card` section instead — same visual language (bold lead line + body text), same
prominence, no collapse/expand interaction. Both were already separate conditional sections in the
shipped page; this is a restyle of each, not a merge.

**`Button`/`Card` (the Base-UI-free shadcn primitives) used where the prototype itself uses them**:
the "try the demo" CTA is now `<Button variant="ghost">` (mirroring the prototype's own
`<Button variant="ghost">`), and `Card` wraps the connect panel, the Kartu art panel, the `dataUse`
card and the `trainingDisclaimer` card, exactly as in `LoginScreen.tsx`. The Strava connect CTA
stays a hand-styled plain `<a>` (not wrapped in the shadcn `Button`) — it is a real navigation link
to an OAuth redirect, not a JS-driven action, and the pre-port page already got this right; wrapping
it in Base UI's polymorphic `render` prop would add risk for no behavioral gain. `Badge` was not
needed anywhere on this route — the prototype itself doesn't use it on Login either (its "Legendary"
tag is a hand-styled `span`, not a `Badge`).

**Flash-info banner deliberately dropped from this slice**, per the dispatch brief — see Open
questions.

**`grounds.json` regenerated by hand** (R4): removing the old flash-banner markup
(`bg-cream/[0.08]` translucent panel) orphaned its `DesignTokenContrastTest` registration; the
Login.tsx entry under `cream/0.08`'s panel-call-site list was dropped to match.

## Open questions

**Flash-info banner deferred, not wired into the restyled page — deliberate scope decision, not an
oversight.** The pre-port page rendered `flash?.info` (Strava OAuth / session-expiry errors) inside
the hero via a `role="status"` banner. The dispatch brief for this slice explicitly instructed
deferring this rather than porting it, so the new page destructures only `demoLoginEnabled` from
`usePage<SharedProps>().props` — `flash` is no longer read on this page at all. A future pass
(likely whichever slice next touches Login, or a dedicated follow-up) needs to design where that
banner lives in the new layout — the hero no longer has the same content shape it did, and the
overlapping connect card changes where a status banner would visually sit.

Nothing else blocking.
